## effect มีไว้ทำอะไร

`useEffect` เป็น hook ที่คนเข้าใจผิดมากที่สุด ไม่ใช่ถังรวม "รัน code หลัง render" งานเดียวของตัวเองคือ **sync component ของคุณกับ external system** — สิ่งที่อยู่นอกการควบคุมของ React: network connection, browser API, third-party widget, subscription, timer

```jsx
useEffect(() => {
  const connection = createConnection(roomId);  // set up external system
  connection.connect();
  return () => connection.disconnect();          // clean it up
}, [roomId]);                                     // re-sync when roomId changes
```

อ่านว่า: "ทำให้ connection sync กับ `roomId`" เมื่อ `roomId` เปลี่ยน React รัน cleanup ของค่าเก่า แล้วรัน effect ของค่าใหม่ เมื่อ component unmount React รัน cleanup ครั้งสุดท้าย

## Dependency และ cleanup

**dependency array** ระบุ reactive value ทุกตัว (prop, state หรือค่า derived) ที่ effect อ่าน React รัน effect ใหม่เมื่อค่าใดค่าหนึ่งเปลี่ยน

- **`[dep1, dep2]`** — รันใหม่เมื่อค่าเหล่านี้เปลี่ยน
- **`[]`** — รันครั้งเดียวตอน mount, cleanup ตอน unmount
- **ไม่ใส่** — รันหลัง *ทุก* render (มักไม่ใช่สิ่งที่ต้องการ)

**cleanup function** ที่คุณ return ต้อง undo สิ่งที่ effect ตั้งไว้ — disconnect, clear timer, remove listener การข้าม cleanup คือแหล่งบั๊กอันดับหนึ่ง: connection ซ้ำ, leak และ listener ที่ยิงหลัง unmount

## คุณอาจไม่ต้องใช้ effect

นี่คือบทเรียนสำคัญที่สุดในทั้งโมดูล effect มีไว้สำหรับ external system ถ้าคุณใช้ effect เพื่อ **transform data สำหรับ render** หรือเพื่อ **ตอบสนอง user event** คุณแทบจะแน่นอนว่าไม่ต้องใช้ effect — และการฝืนใช้ทำให้ code ช้าลงและมีบั๊กมากขึ้น

**อย่า sync derived state ด้วย effect ให้คำนวณตอน render**

```jsx
// 🔴 Avoid: redundant state + an effect to keep it in sync.
const [fullName, setFullName] = useState('');
useEffect(() => {
  setFullName(firstName + ' ' + lastName);
}, [firstName, lastName]);

// ✅ Good: derive it during render — no state, no effect.
const fullName = firstName + ' ' + lastName;
```

สำหรับ derivation ที่ *แพง* ให้ห่อด้วย `useMemo` — ยังไม่ต้องใช้ effect ไม่ต้องมี state เพิ่ม

```jsx
// ✅ Cached derivation, no effect.
const visibleTodos = useMemo(() => getFilteredTodos(todos, filter), [todos, filter]);
```

**อย่าใช้ effect จัดการ user event** logic ที่ควรรันเพราะ user ทำอะไรบางอย่างควรอยู่ใน **event handler** ที่คุณรู้แน่ชัดว่าเกิดอะไรขึ้น

```jsx
// 🔴 Avoid: reacting to a state change with an effect to send analytics.
useEffect(() => {
  if (submitted) post('/analytics', { event: 'submit' });
}, [submitted]);

// ✅ Good: do it in the handler that caused the submit.
function handleSubmit() {
  setSubmitted(true);
  post('/analytics', { event: 'submit' });
}
```

เทสต์เร็ว ๆ: *"นี่กำลัง sync กับสิ่งที่อยู่นอก React หรือเปล่า?"* ถ้าใช่ ใช้ effect ถ้าเป็นการ derive data หรือตอบสนอง interaction ไม่ต้องใช้ effect

<Callout title="สรุปหนึ่งบรรทัด">
`useEffect` มีไว้ **sync กับ external system** (connection, subscription, browser API) — ระบุ reactive value ทุกตัวที่อ่านใน **dependency array** และ return **cleanup** ที่ undo การ setup เสมอ แต่ส่วนใหญ่คุณ **ไม่ต้องใช้ effect**: derive ค่าตอน render (หรือด้วย `useMemo`) และเอา logic ที่ขับด้วย event ไปไว้ใน **event handler** หยิบ effect มาใช้เฉพาะตอน sync กับสิ่งที่อยู่นอก React
</Callout>
