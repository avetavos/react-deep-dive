## Hooks กับ dependency ของมัน

- dependency array ของทุก `useEffect`/`useMemo`/`useCallback` มีทุกอย่างที่ callback อ่านจริง ๆ ครบไหม? ดู **[useEffect & Effects](/react/th/hooks/useeffect-and-effects/)**
- ค่าที่เปลี่ยนบ่อย (callback, theme) ถูกอ่านผ่าน `useEffectEvent` แทนที่จะถูกตัดออกจาก deps ของ effect เงียบ ๆ ไหม? ดู **[AI Bug Catalog](/react/th/reading-react/ai-bug-catalog/)** entry 2
- ทุก hook ถูกเรียกแบบ unconditional ที่ top level ในลำดับเดียวกันทุก render — ไม่เคยหลัง `return` ก่อนเวลา ไม่เคยข้างใน `if` ใช่ไหม? ดู **[AI Bug Catalog](/react/th/reading-react/ai-bug-catalog/)** entry 3
- `useRef<T>()` ได้รับค่าเริ่มต้นแบบชัดเจนเสมอไหม (`null` สำหรับ DOM ref)? ดู **[TypeScript with React](/react/th/tooling-and-production/typescript-with-react/)**
- โค้ดใหม่รับ `ref` เป็น prop ธรรมดาแทนการห่อตัวเองด้วย `forwardRef` ไหม? ดู **[useRef & the DOM](/react/th/hooks/useref-and-the-dom/)**
- `getSnapshot` ของทุก `useSyncExternalStore` return primitive หรือ reference ที่ cache ไว้ ไม่เคยเป็น object/array literal ใหม่ใช่ไหม? ดู **[External Stores](/react/th/state-and-data/external-stores/)**
- ทุก promise ที่ส่งให้ `use()` ถูกอ่านจาก cache ที่เสถียร ไม่เคยถูกสร้างใหม่ใน render body ตรง ๆ ใช่ไหม? ดู **[`use()` & Data Fetching](/react/th/concurrent-and-suspense/use-and-data-fetching/)**
- โค้ด import `useActionState` จาก `react` ไม่ใช่ `useFormState` จาก `react-dom` ใช่ไหม? ดู **[AI Bug Catalog](/react/th/reading-react/ai-bug-catalog/)** entry 8

## Server/client boundary กับ directive

- ทุกไฟล์ที่เรียก client-only hook (`useState`, `useEffect`) หรือแปะ event handler มี `'use client'` จริง ๆ บนตัวเองหรือ parent ใน project ที่รองรับ RSC จริงไหม? ดู **[Server Components](/react/th/react-19/server-components/)**
- ทุก prop ที่ข้ามจาก Server Component ไป Client Component ยังเป็นข้อมูล serializable ธรรมดา (หรือ Server Action จริง) ไม่เคยเป็น function เปล่า ๆ หรือ class instance ใช่ไหม? ดู **[Server Components](/react/th/react-19/server-components/)**
- `dangerouslySetInnerHTML` เคยได้รับ content จาก user โดยไม่ผ่าน sanitizer จริงก่อนไหม? ดู **[AI Bug Catalog](/react/th/reading-react/ai-bug-catalog/)** entry 11
- setter ของ `useOptimistic` (หรือ `requestFormReset`) ถูกเรียกจากข้างใน `startTransition`/Action เสมอ ไม่เคยตรง ๆ จาก event handler ธรรมดาใช่ไหม? ดู **[Forms & useOptimistic](/react/th/react-19/forms-and-useoptimistic/)**

## Key กับ identity

- ทุก `.map()` ที่วน list ใช้ id ที่เสถียรจากข้อมูลเป็น `key` — ไม่เคยเป็น array index และไม่เคยขาดหายไปเลยใช่ไหม? ดู **[AI Bug Catalog](/react/th/reading-react/ai-bug-catalog/)** entry 13–14
- `.map()` ที่จับกลุ่ม sibling element ใช้ `<Fragment key={...}>` (import มาแบบชัดเจน) ไม่ใช่ shorthand `<>` ใช่ไหม? ดู **[AI Bug Catalog](/react/th/reading-react/ai-bug-catalog/)** entry 15
- component editor/detail ใช้ `key={currentItemId}` เพื่อบังคับ reset สะอาด ๆ เมื่อเรื่องที่มันแสดงเปลี่ยน แทนที่จะสะสม internal state ที่ค้างอยู่ใช่ไหม? ดู **[Rendering & Reconciliation](/react/th/foundations/rendering-and-reconciliation/)**

## ใครเป็นเจ้าของ state แต่ละก้อน

- state ตัวนี้คำนวณได้ตอน render แทนที่จะ sync จาก prop ด้วย `useEffect` ไหม? ดู **[useEffect & Effects](/react/th/hooks/useeffect-and-effects/)**
- `setState` เคยถูกเรียกตรง ๆ ข้างใน render body นอกเหนือ event handler หรือ effect ไหม? ดู **[AI Bug Catalog](/react/th/reading-react/ai-bug-catalog/)** entry 17
- ทุก state update ของ object/array เป็น reference ใหม่จริง ๆ ไม่เคยเป็นการ mutate ด้วย `.push`/assign ตรง ๆ แล้วเรียก setter ด้วย reference เดิมใช่ไหม? ดู **[State Snapshot & Purity](/react/th/foundations/state-snapshot-and-purity/)**
- `value` ของ provider ใน Context ถูก memoize (`useMemo`) และมีแค่ข้อมูลที่เปลี่ยนช้าและแชร์กว้าง ไม่เคยเป็นค่าที่เปลี่ยนทุก keystroke ใช่ไหม? ดู **[Context](/react/th/state-and-data/context/)**

## Effect เทียบกับ event

- ทุกการเรียก `set` **หลัง** `await` ข้างใน `startTransition(async () => {...})` อยู่ข้างใน `startTransition` ของตัวเองอีกชั้นไหม? ดู **[Transitions](/react/th/concurrent-and-suspense/transitions/)**
- data fetch ข้างใน effect ยกเลิก request ที่ค้างอยู่ก่อนหน้า (`AbortController`) เมื่อ identifier ของมันเปลี่ยนเร็วไหม? ดู **[useEffect & Effects](/react/th/hooks/useeffect-and-effects/)**
- มี `Date.now()`/`Math.random()` ที่ถูกอ่านตอน render ในโค้ดที่จะ hydrate สักวันไหม — แทนที่จะอยู่ข้างใน effect เท่านั้นหรือส่งลงมาเป็น prop คงที่? ดู **[AI Bug Catalog](/react/th/reading-react/ai-bug-catalog/)** entry 22
- `useLayoutEffect` อ่านค่าที่มีแค่ `useEffect` ตัวพี่น้องเขียน โดยคาดหวังว่าจะเห็น write ของ commit ปัจจุบันแทนที่จะเป็นของ commit ก่อนหน้าไหม? ดู **[Commit Phase & Effects](/react/th/react-internals/commit-phase-and-effects/)**

## Memo pairing กับสมมติฐานของ compiler

- ทุก prop ที่ส่งให้ component ที่ห่อด้วย `memo` เก็บ reference ที่เสถียร — ไม่มี object/array/function literal แบบ inline ที่จุดเรียกใช้ใช่ไหม? ดู **[Memoization & the Compiler](/react/th/hooks/memoization-and-the-compiler/)**
- ถ้า project อ้างว่ารัน React Compiler `babel-plugin-react-compiler` ถูกต่อสายเข้า build จริงไหม — หรือโค้ดแค่สมมติว่ามี auto-memoization ที่จริง ๆ ไม่ได้รันอยู่? ดู **[The React Compiler](/react/th/react-19/the-react-compiler/)**
- return type ของ component ที่ annotate เป็น `JSX.Element`/`ReactElement` เคยต้อง return `null` ไหม? ควรเป็น `ReactNode` แทนหรือเปล่า? ดู **[TypeScript with React](/react/th/tooling-and-production/typescript-with-react/)**
